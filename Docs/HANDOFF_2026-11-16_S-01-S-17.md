## Найденные причины медленной работы (исправлено)

1. Снимок истории перед каждым изменяющим вызовом при откате читал все имена дерева **до** установки
   `CommandInProgress`: 20,7 с на вызов. Флаг теперь ставится в `guard` до снимка; снимок в откате
   запоминает два элемента, между которыми стоит полоса (`'bar'`).
2. `GetFeatures(True)`: win32com оборачивал каждый из 222 объектов (QueryInterface + 2 GetTypeInfo) —
   0,85 с на обход с флагом. Массив читается «сырым», обёртка без QueryInterface (`fastpath._bind`):
   0,004 с + имена 0,1 с. Проверено: 7 методов IFeature дают те же ответы на всех 222 элементах.
3. `_coordinate_of` в `set_dimension` обходил всё дерево (1,2–2,7 с) — теперь `FeatureByName`.
4. Отклонённый вызов: `ForceRebuild3` (8–9 с), хотя ничего не добавлено, и `release_ui` по всем открытым
   документам (5–7 с при 48 документах). Перестроение — только если что-то удалялось; полный сброс UI —
   только если что-то действительно осталось выключенным.
5. `EditFreeze` отвечает 1, если опцию «полоса заморозки» включить при отключённом дереве (так внутри
   вызова инструмента): опция включается при `EnableFeatureTree = True`.
6. Полоса заморозки видна в дереве как элемент типа `LockFeature` — убрана из `_history`.
7. `IPartDoc.GetTessTriangles` и `IComponent2.GetTessTriangles` на SW 2025 SP3 отвечают пусто: рендер
   читает грани тел; сетки компонентов кэшируются по (файл, конфигурация).

## Замечания для продолжения

- Процесс MCP-сервера `solidworks` общий для нескольких чатов на этой машине: вызовы через MCP,
  меняющие текущий документ, сбивают другую сессию. Живые тесты шли отдельным процессом Python из
  окружения uv tool с `sys.path` на рабочее дерево (`live.py`, `t_seq.py`; копии — в тестовой папке
  проекта, вне git).
- Замечено, но не разбиралось: строящие вызовы в контексте правки на большой детали всё ещё 5–10 с
  (`add_plane` 5,6–9,2 с, `sketch_circles` 3,6–7,1 с, `delete_feature` 6–8 с) — кандидаты на профиль.
- `set_dimensions` / `set_dimension`: размер-координата точки от начала координат принимает значение
  **со знаком**; положительное значение для точки на отрицательной стороне переносит её через ноль.
- `read_sketch` (штатный) не читает 3D-эскизы; `read_sketches` читает.
- Диаметр круглого профиля у выреза по траектории — `D3@<элемент>` (возвращается в
  `dimensions.diameter`).
