## Найденные причины медленной работы (исправлено)

1. Снимок истории перед каждым изменяющим вызовом при откате читал все имена дерева до установки
   `CommandInProgress`: 20,7 с на вызов. Флаг ставится в `guard` до снимка.
2. `GetFeatures(True)`: win32com оборачивал каждый из 222 объектов — 0,85 с на обход. Массив читается «сырым»:
   0,004 с + имена 0,1 с.
3. `_coordinate_of` в `set_dimension` обходил всё дерево (1,2–2,7 с) — теперь `FeatureByName`.
4. Отклонённый вызов: `ForceRebuild3` (8–9 с), хотя ничего не добавлено, и `release_ui` по всем открытым
   документам. Перестроение — только если что-то удалялось; полный сброс UI — только если что-то осталось
   выключенным.
5. `EditFreeze` отвечает 1, если опцию «полоса заморозки» включить при отключённом дереве.
6. Полоса заморозки видна в дереве как элемент типа `LockFeature` — убрана из истории.
7. `IPartDoc.GetTessTriangles` и `IComponent2.GetTessTriangles` отвечают пусто: рендер читает грани тел.
8. **`release_ui` обходил открытые документы, первым делом сняв `CommandInProgress`:** 11,5–12,3 с при 56
   документах — на первом вызове каждого процесса сервера и после отказа, оставившего интерфейс выключенным.
   Флаг теперь держится на время обхода: 0,7 с; первый вызов процесса 15,8 с → 3,5 с.

## Замечания для продолжения

- Процесс MCP-сервера общий для нескольких чатов на этой машине: вызовы через MCP, меняющие текущий документ,
  сбивают другую сессию. Живые тесты шли отдельным процессом Python из окружения uv tool с `sys.path` на
  рабочее дерево; сценарии и заметки с замерами — в тестовой папке проекта, вне git.
- Строящие вызовы в контексте правки на большой детали всё ещё 5–10 с (`add_plane`, `sketch_circles`,
  `delete_feature`) — не профилировались.
- `set_dimensions` / `set_dimension`: размер-координата точки от начала координат принимает значение со знаком.
- `read_sketch` (штатный) не читает 3D-эскизы; `read_sketches` читает.
- Слежение за диалогами не отличает окно, открытое самим пользователем в SolidWorks (например, «Параметры»),
  от окна, вызванного инструментом: `DIALOG_BLOCKING` придёт в обоих случаях. Отвечать на окно пользователя
  без его слова нельзя — это записано в описании `dialog_respond`.
- Окно с индикатором хода (`msctls_progress32`) помечается `progress` и блокирующим не считается.
- Ссылки `ref:` хранятся в `<SWMCP_HOME>\refs.jsonl` (до ~14 000, старшая половина отбрасывается при
  переполнении); ссылка на элемент удалённого или откатанного элемента отвечает «gone».
