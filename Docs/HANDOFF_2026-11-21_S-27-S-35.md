## The limit of S-27, and why

The task asked to write the control planes' ratios and the refinement levels "without
automatic recalculation". Verified on Flow Simulation 2025 SP3:

- NIK lists two mesh parameters in the automatic mode (level, gap) and none of the
  others; the classic add-in API's `GlobalMeshSettings.GetParameter` answers E_FAIL
  for every parameter type 0..699 in the automatic and in the manual mode.
- The values follow from switches of the automatic mesh that travel with a project:
  a clone of a project has them, a project created from a template has the
  template's. Writing domain, gap or level does not touch them.
- So the mesh is fixed by WHERE a project comes from, and checked by reading the
  solver's settings file: `flow_create_from_case` clones the reference project (or
  uses a template made from it), then holds every setting against the case.
  Editing the settings file before meshing was not pursued: Flow rewrites it when
  it prepares a calculation, and the solver cannot be started outside Flow.
- Manual mode (`flow_mesh_set({"automatic": false})`) keeps the present mesh when
  the free stream changes - the "no recalculation" part that an API does give.

## Findings that change how runs are compared

- The parallel solver is not bit-repeatable. One project solved twice: goal
  histories identical for the first iterations, then apart. Last values differed
  by about half a percent, averaged values by hundredths of a percent. A tolerance
  of 0.1 % can be met by averaged values, not by last values.
- A project of a model file can change its hidden switches between two days without
  any call of this server showing it (cause not established). A file copy made
  earlier still had the reference setup - the regression therefore takes
  `reference.carrier_model` when that key is set.
- The classic `CopyParameters(project)` carries the hidden switches between
  projects, also across two open documents, and the result matched the case with no
  difference. It also copies the name, and the target ended up in another project
  folder; deleting it emptied that folder. It is not used by any tool. With the
  folder behaviour understood it would remove the need for a template or a carrier.

## For the user

- `git config core.hooksPath .githooks` once per clone (done in this one).
- Optional repository secret `LEAK_DENYLIST` for the CI check.
- Private keys used: `templates_dir`, `cases_dir`, `runs_registry`, `sandbox_dir`,
  `compare_runs_dir`, `reference.*` (new: `reference.carrier_model`),
  `leak_denylist`; new and optional: `flow_folder_slot` ("0/2" on one PC, "1/2" on
  the other) - without it two PCs are told apart only after their folders synced.
- A shared template made from the reference project (Flow Simulation > Project >
  Create Template, on a project that still has the reference setup), put into
  `templates_dir` and entered with `flow_template_record`, is what lets a case be
  used on another model; there is no API to save a template.
- Running servers keep the old code until the client application is restarted.
