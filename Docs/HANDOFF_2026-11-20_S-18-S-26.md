## Что нужно от пользователя

1. **Шаблон Flow с включённым минимальным зазором.** API Flow не умеет включать «Минимальный зазор» в проекте,
   где он выключен; параметр появляется только в проекте, созданном из шаблона с зазором, или в клоне такого
   проекта. Чтобы `flow_create_project(..., min_gap_mm=10)` работал на новых моделях: открыть любой проект с
   включённым зазором (расчётная модель v2 подходит), Flow Simulation → Проект → Создать шаблон, сохранить под
   именем, например, `air_ext_gap` (без `.fwp` — окно дописывает расширение само). Шаблон делать с проекта
   без целей: клонировать проект, удалить в клоне цели, сохранить шаблон, удалить клон. На моделях, где проект
   с зазором уже есть, достаточно `flow_clone`. **Сделано 21.11** — файл назван `air_ext.fwp.fwp`.
2. **Выкладка.** После слияния ветки в `rbr` — обновить основной чекаут и полностью перезапустить приложение
   Claude (выход через значок в трее): сервер вкладки Code порождается приложением и обновляется только так.
   Перезапуск SolidWorks не нужен. Сессия построения при перезапуске приложения теряет связь с сервером.

## Найденные по ходу ошибки (исправлено)

1. Скрипт, стоявший в очереди COM-потока за другим вызовом, **молча пропадал**, если синхронное ожидание
   ответа кончалось раньше, чем до него доходила очередь: `asyncio.wait_for` отменяет то, чего ждёт, а
   COM-поток пропускает отменённое задание. Запись задания оставалась `queued` навсегда.
2. Имя эскиза, оставленного открытым упавшим скриптом, читалось через интерфейс `IFeature` без запроса
   интерфейса и приходило матрицей преобразования (совпадение номеров членов у разных интерфейсов).
3. После удаления активного проекта Flow активного проекта не оставалось, а сообщение говорило «в документе
   нет проекта».

## Замечания для продолжения

- Во время расчёта Flow не менять проект решаемого документа (`flow_set_conditions`, `flow_delete` на нём):
  сервер этого не запрещает. Остальные документы и инструменты свободны.
- Вопросы Flow («сбросить область?», «подстроить сетку?») отключены на всё время расчёта и включаются по его
  окончании; если процесс сервера завершится посреди расчёта, они останутся отключёнными до перезапуска
  SolidWorks, а `flow_status` покажет состояние `lost` и то, что записал решатель.
- Запуск решателя без SolidWorks (чтобы расчёт пережил его закрытие) не получился: лицензию `efdsolver.exe`
  получает только будучи запущенным из SolidWorks. Подробности — в `RBR.md`, раздел 1.12.0.
- `typed.Auto` определяет интерфейс запросом `QueryInterface` при первом обращении к члену с новым именем:
  на цикле по тысячам граней это один лишний COM-вызов на объект.
- `sketch_move` проверяет точки сегментов (концы, центры, точки сплайна); у текста и эллипса проверяемых
  точек нет — перенос выполняется без сверки, об этом сказано в ответе.
- `rebuild_chain` смотрит только детали (`.SLDPRT`) в названных папках, без вложенных; сборки, использующие
  эти детали, не перестраивает.
- Вопрос SolidWorks «Да / Нет» при открытии детали с внешними ссылками (штатный `open_part`) закрывается сам
  через 10–20 с; `DIALOG_BLOCKING` успевает прийти раньше, вызов после этого продолжается. Отвечать на него
  не нужно. `rebuild_chain` и `update_external_refs` грузят детали без окна и без вопросов.
- `rebuild_chain`: на загруженной машине 17–30 с на деталь (загрузка без окна, перестроение, сохранение на
  сетевой диск), поиск зависимостей — 2–14 с на 19–25 файлов. В ответе есть время по каждой детали (`seconds`)
  и время поиска (`scan`).
- На машине к концу дня открыто 54 документа, GDI 72–74 %, вызовы в 3–4 раза медленнее утренних
  (`sketch_rect` 26 с против 7). Перед длинной работой — `close_hidden_documents`.
